# Mickey Companion 产品架构

## 产品定位

米奇是一个低打扰、常驻桌面的陪伴型桌宠。核心价值是可见的生命感和轻量互动：平时安静呼吸，在自然间隔内偶尔踩奶或打喷嚏，用户也可以点击或从托盘立即触发动作。

## 体验原则

1. **安静常驻**：空闲动画是主状态，定时动作低频出现，不抢占用户工作。
2. **行为一致**：所有动作都由 Rust 后端统一确认和广播，点击、定时器和托盘不会形成不同的播放路径。
3. **可恢复**：位置与大小持久化；屏幕布局变化后自动回到可见区域；隐藏后可从托盘找回。
4. **可配置**：便携版读取应用旁的 `rules.json`，安装版使用用户数据目录中的可写副本。保存规则后自动更新点击映射和定时器。
5. **可发布**：资源在打包阶段进入应用，最终产物只在全部资源就位后签名。

## 运行数据流

```text
rules.json ──> Rules 解析与规范化 ──> Scheduler
                    │                    │
                    └── rules_changed ──> 前端点击映射
                                         │
点击 / 托盘 / 定时器 ──> 后端 trigger ──> SpriteSheet 播放一次
```

## 组件职责

- `src-tauri/src/config.rs`：规则读取、默认值、输入规范化。
- `src-tauri/src/timer.rs`：基于单调时钟的动作调度。
- `src-tauri/src/window_state.rs`：位置与缩放持久化、高分屏坐标计算、可见区域约束。
- `src-tauri/src/app.rs`：Tauri 生命周期、托盘、规则监听、动作事件和窗口控制。
- `ui/`：只负责动画呈现和鼠标意图识别，不独立决定运行状态。
- `scripts/build.sh`：可分发目录组装和 macOS 最终签名。

## 后续迭代边界

- 新动作应同时增加动作枚举、精灵资源、帧节奏和规则验证，并让触发继续经过后端事件总线。
- 若增加可视化设置页，应编辑同一份规则源，避免另建配置状态。
- 公共发布前应把 ad hoc 签名替换为 Developer ID，并加入 Apple notarization；Windows 需要分别验证 MSI 与 NSIS 安装后的配置路径。
- 菜单的当前缩放和暂停状态可升级为可勾选项，这是体验增强，不影响当前运行正确性。
